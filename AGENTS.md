## Commands

Run from repository root. Apply fixes before verification.

| Scope | Fix | Verify |
| --- | --- | --- |
| Toolchain | `go install github.com/wailsapp/wails/v2/cmd/wails@latest` | `wails version` |
| Frontend deps | `cd frontend && npm install` | — |
| Go | `go fmt ./...` | `go vet ./...`; `go test ./pkg/...` |
| Generated data | `go generate ./pkg/sysinfo/...` | — |
| Frontend | `cd frontend && npm run lint && npm run format` | `cd frontend && npm run format:check`; `cd frontend && npm run type-check`; `cd frontend && npm test` |
| Build | — | `wails build` |

- Local ESLint does not catch Prettier issues; CI does. Run `npm run format` before pushing.

## Testing and verification

- **Go:** `go test ./pkg/...` — root `app_test.go` is excluded because it needs the Wails runtime.
- **Frontend:** `cd frontend && npm test` — Vitest.
- **Environment:** `frontend/dist` is generated by `wails build`, not committed, and is required by `//go:embed` in `main.go`. CI scaffolds a placeholder before the Go steps.
- Ladder: `go vet ./...` → `go test ./pkg/...` → frontend type-check and tests → `wails build`.

## Boundaries

### Always

- Keep `frontend/wailsjs/**` generated; regenerate with `wails dev` or `wails build`.

### Ask first

- Shared-component API changes — consolidate the requirement and propose canonical alternatives before editing.

### Never

- Commit secrets or local environment values.
- Hand-edit `frontend/wailsjs/**`.
- Modify `.github/workflows/**` without explicit human instruction.
- Modify `vendor/**`, `node_modules/**`, or installed dependency contents.
