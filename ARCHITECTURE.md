# install-it — architecture

This file is the source of truth for repository structure, code placement, and domain contracts.

## Repo structure

Standard Go and Vue/Vite layout follows official conventions; only project-specific deltas are listed.

- `pkg/` — Go domain packages, one concern per package.
- `frontend/src/` — Vue 3 application.
- `frontend/wailsjs/` — generated Go→JS bindings; regenerated by `wails dev` / `wails build`.
- `conf/setting.json` — app settings on disk, not SQLite rows.
- `drivers/` — user-supplied installers; created next to the binary at startup.

## Code placement

- Place types by ownership: inline for one file; exported beside the logic that owns them; `frontend/src/types/` only for shared vocabulary with no single owner. A shared type makes every caller re-enforce the owner's invariant.
- Add new Go structs exposed to the frontend to `Bind` in `main.go`, and enums to `EnumBind` — bindings are generated from that list.
- Lint and format targets are decided by `frontend/eslint.config.js` and `.prettierignore`; not restated here.

## Storage and settings contracts

### SQLite

- Keep the dependency set CGO-free.
- Route schema changes through `gormigrate/v2` migrations in `pkg/storage/db.go`. Never call `AutoMigrate` outside a migration.
- Keep app settings in `conf/setting.json` through `FileStore` / `MemoryStore`, not in SQLite.

### Import and export

- `porter.Porter` closes the DB before backup, then calls `db.Reopen()` and `db.Migrate()` after import. Storage code on this path must survive the close/reopen.

## Wails runtime contracts

### Bindings

- Generated bindings all return promises.
- The frontend imports bindings from `@/wailsjs/go/<package>/<Struct>`.

### Startup

- `main.go` `init()` creates `conf/` and `drivers/` next to the binary; root-level `app_test.go` relies on that being harmless.
- The app is Windows-only. The release pipeline builds amd64 only (`.github/workflows/build_and_release.yml`); CGO-free dependencies make other targets possible but CI does not build them.

### Errors

- `errcode.Error` has no `Is()` method. Only package-level sentinels work with `errors.Is`; constructing `errcode.New("same-code")` at each call site defeats it.

## Update contracts

- Self-update uses the Windows file-rename trick and spawns a detached process.
- `TriggerNativeUpdate` calls `os.Exit(0)`, so it cannot be tested end to end; only `extractBinaryFromZip` is unit-tested.
- The Python updater is a separate repository (`install-it-updater`), not part of this tree.

## Build contracts

### Generated data

- `pkg/sysinfo/pciids.go` declares a `go:generate` directive that fetches `pci.ids.gz`. CI runs `go generate ./pkg/sysinfo/...` before tests.
- `frontend/dist` is generated by `wails build`, not committed, and is required by the `//go:embed` directive in `main.go`. CI creates a placeholder before Go steps.
